# 실기기 검증 (Galaxy S26 Ultra)

개발 PC 에서는 확인할 수 없었던 항목이다. 하나씩 해 보고 결과(날짜, 값, 실패 조건)를 이 파일에 적는다.
확인 전에는 "된다"고 말하지 않는다.

## A. 앱 · 모델

| # | 확인할 것 | 방법 | 결과 |
|---|---|---|---|
| A1 | APK 설치·실행 | `adb install -r …/app-debug.apk` | |
| A2 | MOCK 엔진으로 "서버 시작" → 온라인 | 최초 설정에서 MOCK 선택. 웹 랜딩의 상태가 온라인으로 바뀌는지 | |
| A3 | 웹에서 질문 → MOCK 답변 도착, 화면에 MOCK 표시 | | |
| A4 | GenieX 초기화 | 엔진을 GenieX 로. 기록에 "GenieX SDK 초기화" 뒤 오류가 없는지 | |
| A5 | 모델 내려받기 | 진행률 표시, 중간에 앱을 껐다 켜도 이어받는지 | |
| A6 | 모델 로딩 | 진단 패널: 모델 파일 경로, 런타임, 로딩 시간 | |
| A7 | **실제 연산 장치** | 연산 장치를 NPU / GPU / CPU 로 각각 바꿔 로딩. 로딩 성공 여부와 "최근 생성 속도"를 비교해 기록. `adb logcat` 에서 GenieX/QNN 로그로 백엔드 확인 | |
| A8 | 한국어 답변 품질 | 표준 질문 3개 + 함정 질문("구리 식각률은?", "−40도가 왜 제일 느려?")에 규칙을 지키는지 | |
| A9 | `#동작:` 태그 | 모델이 태그를 붙이는지, 안 붙여도 주제 기본 동작으로 넘어가는지 | |
| A10 | 응답 시간 | 대시보드의 중앙값. 10초를 넘으면 더 작은 모델·더 짧은 `MAX_TOKENS` 검토 | |
| A11 | 발열 | 20분 연속 질문 후 "발열 상태". '뜨거움' 이상이면 쉬는 주기 필요 | |

`adb logcat` 예:

```bash
adb logcat -s GenieX:* QNN:* RabbitServer:*
```

(태그 이름은 SDK 버전에 따라 다를 수 있다. 처음에는 필터 없이 보고 실제 태그를 여기에 적는다.)

모델 후보를 고를 때: 한국어를 제대로 하는지가 먼저다. 0.6B 급은 동작 확인용으로만 보고,
실기기에서 더 큰 모델(예: 4B 급 AI Hub 모델, NPU)을 시험한다. 어떤 모델이 이 기기 NPU 에서 도는지는 로딩해 봐야 안다.

## B. 서비스 유지

| # | 확인할 것 | 결과 |
|---|---|---|
| B1 | 화면을 끄고 10분 뒤에도 웹에서 질문이 답해지는가 | |

| B8 | Android 버전별 포그라운드 서비스 동작 (기기의 실제 버전 기록) | |
