# 데스크탑 서버 (LM Studio + Gemma 4)

폰의 GenieX 대신 전시자 PC 가 답하는 구성이다. 관람객이 보는 주소는 Cloudflare Worker 릴레이로 고정되고,
PC 는 그 릴레이에 **바깥으로 접속만** 한다. 공유기 포트를 열거나 LM Studio 포트를 인터넷에 노출하지 않는다.

```
관람객 폰(WebAR)  ──wss──▶  rabbit-ar-relay.<계정>.workers.dev  ◀──wss──  이 PC (scripts/desktop-device.ts)
                                                                            └─ http://127.0.0.1:1234  LM Studio
```

## 켜는 법

1. 저장소 루트에 `desktop-server.env` 가 있어야 한다 (`desktop-server.env.example` 참고. git 에 올라가지 않는다).
2. `토끼 서버 시작.bat` 을 더블클릭한다. LM Studio 가 꺼져 있거나 모델이 내려가 있으면 서버가 알아서 켜고 올린 뒤 예열하고 릴레이에 붙는다. 서버가 예기치 않게 죽으면 5초 뒤 다시 켜진다.
3. 창에 `릴레이 연결됨` 이 보이면 준비 끝. 창을 닫으면 서버가 꺼지고, 웹은 미리 준비한 답변으로만 응답한다.

전시 중에는 PC 가 절전에 들어가지 않게 한다.

**서버는 한 번에 하나만 켠다.** 같은 토큰으로 두 번째 서버를 켜면 릴레이가 먼저 켜진 쪽을 끊는다.
먼저 켜진 서버는 "다른 창에서 토끼 서버가 켜져서 이 서버는 멈춥니다" 를 찍고 스스로 꺼진다
(예전에는 양쪽이 서로 연결을 빼앗으며 몇 초마다 끊겼다).

## 안정성: 고장이 났을 때 스스로 하는 일 (2026-11-19 보강)

전시 내내 사람 손 없이 버티는 것이 목표다. 기록은 창과 `logs/desktop-server-날짜.log` 양쪽에 남는다.

| 상황 | 토끼 서버가 하는 일 | 그동안 관람객 화면 |
|---|---|---|
| LM Studio 서버가 꺼짐 | 30초마다 점검하다 발견하면 `lms server start` 로 다시 켠다 (질문이 실패하면 즉시 점검) | 미리 준비한 답변 |
| 모델이 내려감, 문맥 길이가 짧게 올라옴 | `lms load` 로 다시 올리고 예열한다. 실패하면 30초 뒤 다시 시도 | 미리 준비한 답변 (예열 중에는 모델을 부르지 않는다) |
| 모델이 글자를 내다 멈춤 | 첫 글자 70초, 글자 사이 45초, 전체 150초 제한에 걸리면 끊는다 | 미리 준비한 답변 |
| 모델이 숨은 메모(`<생각>`)를 닫지 않음 | 첫 빈 줄까지를 메모로 보고 나머지를 답으로 쓴다 | 정상 답변 |
| 릴레이 연결이 끊김 | 만들던 답을 멈추고 1초부터 30초까지 늘려 가며 다시 붙는다. 3번 연속 실패하면 원인(토큰 틀림 / 인터넷 끊김)을 창에 알려 준다 | 한 번은 조용히 다시 보내고, 안 되면 미리 준비한 답변 |
| 연결이 겉보기엔 살아 있는데 죽음 (절전에서 깨어남, 공유기) | 20초마다 ping 을 보내고 50초 동안 답이 없으면 끊고 다시 붙는다 | 위와 같음 |
| 같은 토큰으로 서버가 하나 더 켜짐 | 릴레이에 정말 다른 서버가 붙어 있는지 확인한 뒤 먼저 켠 쪽만 멈춘다 | 영향 없음 |
| 코드에서 예상 못 한 오류 | 그 질문만 실패 처리하고 계속 돈다. 프로세스가 죽으면 bat 이 5초 뒤 다시 켠다 | 미리 준비한 답변 |
| PC 절전 | 서버가 켜져 있는 동안 절전에 들어가지 않게 요청한다 (`KEEP_AWAKE=0` 으로 끔). 화면 꺼짐은 막지 않는다 | — |

관람객 쪽(웹)은 연결이 끊기면 바로 다시 붙고(화면으로 돌아올 때·네트워크가 돌아올 때 포함), 질문 도중 끊기면 한 번 다시 보낸다.
웹소켓이 막힌 네트워크에서는 일반 HTTP 요청으로 묻는다(스트리밍 없이 완성된 답만 온다).
서버가 아무 소식 없이 멈추면 80초(스트리밍 중에는 60초) 뒤 미리 준비한 답변으로 넘어간다.

### 고장 주입 시험 (2026-11-19, 로컬 릴레이 + 실제 모델)

| 주입한 고장 | 결과 |
|---|---|
| 모델이 내려간 상태에서 서버 시작 | 9초 만에 다시 올리고 49초 예열 뒤 정상 답변 |
| LM Studio 서버 끄기 | 직후 질문은 준비된 답변. 서버는 5초 안에 다시 켜짐 |
| 모델 내리기 | 다음 점검에서 다시 올리고 예열(42초) 뒤 모델이 답함 |
| 릴레이 죽였다가 12초 뒤 다시 켜기 | 4번 재시도 끝에 다시 붙음 |
| 서버 두 개 켜기 | 먼저 켠 쪽만 멈춤 |
| 서버를 25초마다 교체 | 브라우저 질문 5개 모두 모델이 답함 |
| 브라우저에서 웹소켓 차단 | HTTP 로 모델 답을 받음 |

재지 않은 것: 몇 시간 연속 운영, 여러 명 동시 접속, 실제 전시장 네트워크, PC 가 실제로 절전에 들어갔다 깨어나는 경우.
시험 중 모델을 다시 올리는 명령이 한 번 취소된 적이 있다(시험 스크립트가 같은 순간에 모델을 내린 탓으로 보인다). 그 경우에도 다음 점검에서 복구됐다.

## 모델에 넣는 것

매 질문마다 같은 시스템 프롬프트를 넣는다 (`packages/educational-content/src/index.ts` 의 `fullSystemPrompt`).

- 토끼 선생님 페르소나와 지침 (`desktop_prompt_ko.json` 의 `system_prompt`): 아무것도 모르는 사람에게 설명한다는 전제, 결론부터·단계별·비유, 보통 4~6문장·깊은 질문은 8~12문장, 일반 과학과 잡담도 받아 줌
- 쉬운 설명용 배경지식 (`desktop_prompt_ko.json` 의 `primer`): 플라즈마, 식각, self-bias, 칠러, 열 접촉, SiC 등. 측정값은 넣지 않는다
- 포스터 사실 요약 전부 (`facts_digest`)
- `poster_facts.json` 원본 전체
- 장면별 설명 대본 (`scene_scripts_ko.json`)
- 모범 답변 (`qa_ko.json` 의 답변들)

같은 세션의 직전 대화 4턴도 함께 넣어 "더 자세히" 같은 후속 질문을 받는다.

## 답변 검사

- 동작 태그(`#동작: …`)는 allowlist 에 있는 것만 받는다. 모델이 무난한 `rabbit_explain` 을 고르면 질문 주제에 맞는 장면으로 바꾼다.
- 모델은 답을 쓰기 전에 `<생각>…</생각>` 안에 짧은 메모를 먼저 쓴다. 이 부분은 관람객에게 보내지 않는다.
- 지어낸 측정값으로 보이는 문장만 뺀다: 자료(포스터·배경지식·질문)에 없는 숫자가 있고, 그 문장이 이 실험의 측정을 말하며, '보통·일반적으로·추측' 같은 표지가 없을 때. 일반 과학 설명의 숫자는 둔다. (2026-11-19 이전에는 숫자 하나만 어긋나도 답 전체를 버렸다.)
- 답변 길이 한도는 2400자, 모델 호출 한도는 150초다. 넘거나 실패하면 미리 준비한 답변을 보낸다.
- 이 검사는 숫자만 본다. 시험 중 모델이 칠러 설정 '−20°C'를 '−0°C'로 잘못 옮기거나, 포스터에 없는 서술을 덧붙인 적이 있다. 지침으로 줄였지만 없어졌다고 확인하지는 못했다.
- 화면에는 `전시자 PC의 로컬 AI` 배지가 붙는다.

## 실측 (2026-11-19, 이 PC: RTX 4070 Ti SUPER 16GB, gemma-4-26b-a4b-it-uncensored Q4_K_M, 문맥 16384)

`npm run try:desktop` (로컬 릴레이 + 실제 모델, 질문 8개):

- 8개 모두 모델이 답했고 숫자 검사에 걸린 것은 없었다.
- 예열 전 첫 질문: 첫 글자까지 28.6초. 그 뒤로는 첫 글자 2.5~3.6초, 전체 8.5~16.6초.
- 범위 밖 질문("점심 뭐 먹을까"), 프롬프트 탈취 시도, 자료에 없는 조건("영하 100도")은 모두 거절하거나 범위 밖이라고 답했다.

이 측정은 질문 8개짜리 한 번이다. 여러 사람이 동시에 물을 때의 대기 시간은 재지 않았다 (모델은 한 번에 한 질문만 처리한다).

## 알아 둘 점

- 지금 모델은 `uncensored` 변형이다. 주제 제한과 출력 검사는 있지만, 불특정 다수에게 공개하는 전시에는 공식 Gemma 4 instruct 모델이 더 안전하다. 바꾸려면 `desktop-server.env` 의 `LMSTUDIO_MODEL` 과 bat 파일의 모델 이름을 고친다.
- 모델(15.6GB)이 VRAM 16GB 를 거의 다 쓴다. 다른 GPU 프로그램(ComfyUI 등)과 같이 돌리면 느려지거나 실패한다.

## 길어진 답변의 속도 (2026-11-19)

새 지침으로 로컬 릴레이에서 잰 값: 보통 질문 약 25~50초(400~700자), 깊은 질문 약 75초, 잡담 약 23초. 첫 글자는 2~4초 뒤부터 나온다.
이 측정 중에는 다른 서버 창도 같은 모델을 쓰고 있어서 실제보다 느리게 나왔을 수 있다. 서버 하나만 켠 상태의 값은 다시 재지 않았다.
