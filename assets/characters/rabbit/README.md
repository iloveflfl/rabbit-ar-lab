# 토끼 선생님 — 2D 캐릭터 자산

**상태: 확정.** 소유자가 2026-11-18 에 이 디자인을 승인했다 (`character_lock.json` 의 `approved_design: true`).
인계 패키지에는 캐릭터 원화가 없었기 때문에, 새로 디자인한 토끼를 2D 벡터 리그로 만들었다.
기존 캐릭터를 본뜨지 않았다.

## 단 하나의 원본

`apps/web-ar/src/rabbit/rig.ts` — 부위별 벡터 도형과 관절(pivot).
화면에 나오는 토끼, 이 폴더의 모든 시트, 랜딩의 토끼, 새 포스터 머리띠의 토끼가 전부 이 파일에서 나온다.
그래서 장면마다 그림체·비율·색이 달라질 수 없다. 외형을 바꾸려면 이 파일만 고치고 시트를 다시 뽑는다.

```bash
npm run export:rabbit
```

## 이 폴더의 파일

| 파일 | 내용 |
|---|---|
| `character_master_front.svg` | 기준형 (정면, 기본 표정) |
| `character_expression_sheet.svg` | 표정 8종: neutral, smile, explain, surprised, confused, proud, worried, relieved |
| `character_pose_sheet.svg` | 포즈 12종: standing, waving, pointing ×2, talking, surprised, cooling ×2, cheering, thinking, arms_open, leaning |
| `character_lock.json` | 색·선·비율·고정 특징 (리그에서 자동 추출) |
| `clips.json` | 애니메이션 클립 8종의 길이·반복 여부·설명 |
| `qa/` | 검수 기록을 넣는 곳 (아직 비어 있음) |

시트는 SVG 다. 명세가 말한 PNG 시트는 만들지 않았다(벡터 원본이 있으므로 필요할 때 어떤 해상도로든 뽑을 수 있다).

## 없는 것 — 있는 척하지 않는다

- **3/4 · 측면 · 후면 턴어라운드**: 없다. 리그는 정면 한 방향이다.
  AR 에서는 토끼 평면이 항상 카메라를 바라보게(billboard) 해서 정면만 보여 준다.
  다른 각도가 필요하면 각도별 2D 리그를 따로 그려야 한다. 3D 모델로 대신하지 않는다.
- **스프라이트 시트 / 아틀라스**: 없다. 프레임 이미지가 아니라 실행 중에 리그를 캔버스에 그린다
  (520×600 디자인 화면을 1~1.5배로). 그 캔버스가 3D 공간의 평면 한 장에 붙는다.
- **검수 기록**: `qa/` 는 아직 비어 있다. (디자인 승인은 받았다.)

## 디자인 요약

- 종: 토끼 수인, 약 2등신의 치비 비율
- 고정 특징: 긴 귀 2개(안쪽 분홍, 오른쪽 귀가 조금 더 기울어 있음), 주둥이와 ω 입·앞니, 볼 털과 이마 털, 분홍 볼터치, 짧고 둥근 꼬리
- 복장: 흰 실험 가운(하늘색 밑단·소매), 노란 나비넥타이, 주머니의 눈꽃 심벌(극저온)
- 소품: 별 달린 포인터 (가리킬 때만 나타남)
- 그림 안에 글자를 넣지 않는다
- 선: 따뜻한 갈색 `#6A4636`, 굵기 5 (디자인 단위), 둥근 모서리

## 애니메이션

스프라이트가 아니라 리그 부위의 보간이다 (`apps/web-ar/src/rabbit/clips.ts`).

| 클립 | 동작 |
|---|---|
| `rabbit_idle` | 숨쉬기, 귀 살랑임, 눈 깜박임, 가끔 귀 털기 |
| `rabbit_talk` | 입 모양 변화, 작은 손짓 |
| `rabbit_point` | 포인터로 가리키기 (왼쪽/오른쪽) |
| `rabbit_surprised` | 폴짝, 눈 커짐, 두 귀 번쩍 |
| `rabbit_cooling` | 버튼을 꾹 누르고 시원해하기 |
| `rabbit_cheer` | 두 팔 들고 두 번 뛰기 (착지 때 눌림) |
| `rabbit_think` | 고개 갸웃, 앞발을 볼에 |
| `rabbit_wave` | 손 흔들기 |

클립 사이는 0.24초 동안 섞인다. 귀는 몸의 위아래 움직임을 반 박자 늦게 따라온다(스프링).
LLM 은 정해진 동작 ID 만 고를 수 있고, 실행 중에 그림을 새로 만들지 않는다.

## 검수할 때 볼 것 (CHARACTER_2D_BIBLE §4)

- [ ] 모든 표정에서 머리 폭·귀 뿌리·눈 위치가 같은가 (리그에서 나오므로 구조적으로 같다. 눈으로 확인)
- [ ] 포즈마다 손·발·귀 실루엣이 깨지지 않는가
- [ ] 부위 겹침 순서가 맞는가 (특히 팔을 올렸을 때 머리와의 앞뒤)
- [ ] 휴대폰 화면 크기에서 표정이 읽히는가
- [ ] AR 화면에서 가장자리에 흰 테두리(알파 헤일로)가 없는가
